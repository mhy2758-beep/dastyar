PHASE 3 — REAL INSPECTION WORKFLOW

Phase 2 is complete and verified.

Do NOT rebuild the application.
Do NOT change the existing visual design unnecessarily.
Do NOT replace SQLite.
Build on the existing SQLite + Repository architecture.

The goal of Phase 3 is to implement the first real construction inspection
workflow:

PROJECT → VISIT → STAGE → CHECKLIST → PHOTOS → NOTES

==================================================
1. VISIT DATA MODEL
==================================================

Create a normalized SQLite table:

visits

Fields:

id
project_id
stage_id
visit_date
start_time
end_time
title
description
status
created_at
updated_at
sync_status

Relationships:

Project 1 → many Visits
Stage 1 → many Visits

A visit must always belong to a project.

==================================================
4. CHECKLIST ARCHITECTURE
==================================================

Implement the checklist system properly.

Create these SQLite tables:

checklist_templates
checklist_items
checklist_snapshots
checklist_records

Relationships:

Stage
↓
Checklist Template
↓
Checklist Items

When a new visit is created:

Current checklist template for that stage
↓
Create immutable checklist snapshot
↓
Create checklist records for that visit

IMPORTANT:

A visit must use a SNAPSHOT of the checklist.

If the checklist is edited later, historical visits must NOT change.
