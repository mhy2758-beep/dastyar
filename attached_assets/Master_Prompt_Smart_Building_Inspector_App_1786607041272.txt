MASTER PROMPT — Smart Building Inspector App

Phase 1: Architecture, Project Setup & Foundation

You are a senior full-stack mobile application architect and engineer.

We are building a professional mobile application for a building construction inspector in Iran.

The application is Persian-first, RTL, mobile-first, offline-capable, and designed specifically for real construction-site inspection work.

The application should eventually provide:

- Project management
- Construction stage management
- Site visit management
- Editable stage-based checklists
- Photo documentation
- Text notes
- Voice notes
- Voice-to-text
- Violation management
- AI-assisted technical report generation
- Iranian building regulation knowledge base
- Project document management
- PDF report generation
- Google Drive synchronization
- Offline-first operation
- Search
- Professional dashboard

IMPORTANT:
Do not attempt to build every feature in this phase.

First create a stable technical foundation and architecture.

==================================================

1. TECHNOLOGY
   ==================================================

Use a modern mobile-first architecture.

Preferred stack:

Frontend:
React Native + Expo + TypeScript

Backend:
Node.js / TypeScript

Database:
PostgreSQL on the backend

Local mobile database:
Expo SQLite

Authentication:
Secure authentication with Google-compatible authentication architecture.

Cloud storage:
Google Drive integration will be added in a later phase.

AI:
Gemini API will be integrated through the secure backend.

The architecture must allow the application to work offline.

Do not expose API keys or private credentials inside the mobile application.

==================================================
2. PRODUCT DESIGN

The app is called:

"دستیار مهندس ناظر"

Use a professional engineering visual language.

UI requirements:

- Persian
- RTL
- Clean
- Minimal
- Professional
- Fast
- Large touch targets
- Suitable for one-handed construction-site use
- Light mode
- Dark mode

Avoid unnecessary animations and decorative elements.

Use a modern Persian font such as Vazirmatn if technically appropriate.

10. OFFLINE-FIRST FOUNDATION

The mobile application must be designed around offline-first principles.

Create the architecture for:

Local database
Local records
Sync status
Sync queue
Conflict handling

Each syncable record should be capable of having a state such as:

LOCAL
PENDING
SYNCING
SYNCED
ERROR

Do not implement the complete synchronization engine yet.

However, do not design the application in a way that would prevent offline
support later.

12. CODE QUALITY

Use TypeScript strictly.

Use clear folder structure.

Separate:

UI
Business logic
Database
API
Services
Models/types
Utilities
Configuration

Do not place all application logic inside screen components.

Create reusable components.

Use environment variables for secrets.

Do not hard-code API keys.

==================================================
13. RESPONSIVE MOBILE UI

The primary target is Android.

The application must also remain compatible with iOS architecture.

Make sure:

- RTL works correctly
- Persian text displays correctly
- Buttons are touch-friendly
- Keyboard handling is correct
- Forms are scrollable
- UI works on common Android screen sizes

==================================================
14. ERROR HANDLING

Create a consistent error-handling architecture.

Do not allow uncaught errors to crash the application.

Create user-friendly Persian error messages.

Log technical errors separately from user-facing messages.
